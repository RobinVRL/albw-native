# Robustness worklist: Ghidra functions that are wrong natively

Generated by `native/robust/tools/` (see "Regenerating" below). Each rewrite lives in
`native/robust/func_<USA>.c` (one strong `func_<USA>` per file) and is marked "yes" in the
"done" column. **These files are not linked yet:** `tools/link.sh` builds `native/game/*.c`,
`native/sdk/*.c`, `native/runtime/*.c` only. To use them, add `native/robust/*.c` to its
`NATIVE` list (they compile clean with `-Wall -Wextra`, no `albw_native.h` needed; they include
`robust.h` from their own directory).

## Classes

- **A: uninitialised register input.** The Ghidra C reads `in_rN`, `in_lr`, `in_sN`/`in_dN`,
  `unaff_rN` or `extraout_rN`/`extraout_sN`: a value the ARM code received in a register Ghidra
  did not model. Natively that is an uninitialised local.
- **B: unrecovered computed jump** (`UNRECOVERED_JUMPTABLE`). In this game **none of them is a
  switch table** (0 of 710 jump through a `ldr pc,[pc,rX,lsl #2]` / `add pc,pc,rX,lsl #2` table;
  Ghidra resolved all of those). Every one is an indirect **tail call** (`bx rX`), almost always the
  ARM C++ pointer-to-member-function dispatch of the game's state machines
  (`{ptr, adj}`: `this += adj >> 1; fn = adj & 1 ? vtable[ptr] : ptr; fn(this, ...)`).
  The broken ones are those where Ghidra emitted `(*UNRECOVERED_JUMPTABLE)()` with **no
  arguments**: natively the handler gets a garbage `this`.

Counts (Ghidra-sourced functions that are compiled into the game and have no native override;
@NATIVE@ functions already have native versions and were skipped):

| | functions |
|---|---|
| flagged class A (by name) | @RAW_A@ |
| flagged class B (by name) | @RAW_B@ |
| both | @RAW_AB@ |

## How the list is ranked

1. **Entry points** (@ROOTS@): the 1,230 static constructors (`gen_data.init_tables`), 00100C18,
   00100C90, 00100F68, and the sead framework / main-loop functions named in
   `native/GRAPHICS_STACK.md` (0049546C 004960AC 00496238 004964F8 004966A4 004970E8 00497DBC
   00499738 0049A188 0049A944).
2. **Call graph**: direct `func_XXXXXXXX` calls in the Ghidra C (`build/ghidra_analyzed2`,
   `build/ghidra_extra`, Ghidra `FUN_<EU>` names mapped to USA) plus the calls made by the native
   overrides. BFS depth from the entry points; "-" = not reachable by direct calls (most such
   functions are reached through vtables / PMF tables, so "-" does not mean dead).
3. Sort by depth, then by number of distinct direct callers.
4. **Filtering** (`benign.py`): a flagged register whose every use is a whole argument to a callee
   that never reads that parameter is harmless (Ghidra over-counted the callee's parameters:
   e.g. 237 call sites pass `extraout_r1` to 00169A80, which only takes r0). "Never reads" is
   decided by the ARM **entry live-in analysis** (`livein.py`, below) when available, else
   transitively on the Ghidra C.
5. **Verdicts** per register come from the live-in analysis: an `in_sN`/`in_rN` that is live-in at
   the function entry is a missing parameter; one that is not live-in is a callee's result that
   Ghidra lost because it typed the callee `void` (typical: `in_s0` right after a call to a
   float-returning leaf).

The SDK column marks functions in `native/sdk_areas.json` / `sdk_map.json`: `SDK-os(...)` ones
(services, svc, kernel) will be replaced at the API level by native/sdk and are not worth a
faithful rewrite; plain `SDK(...)` ones (math, crt, framework helpers) are pure code and are.

## Findings beyond the A/B names (important)

- **Float bit reinterpretations compiled as value conversions.** Ghidra prints a same-size
  int<->float reinterpretation as a C cast: `(float)param_1[0x22]` where the ARM does
  `vldr s1, [r4, #0x88]`, `param_1[0x22] = (int)fVar13` for a `vstr`, `(int)f > 0x7F7FFFFF` for
  `vmov r2, s0; cmp r2, r7`, `(float)func_00691F30(...)` for a soft-float helper's r0. Real
  conversions appear as `VectorSignedToFloat`/`VectorUnsignedToFloat`/`VectorFloatTo*` in this dump.
  The converter keeps the C meaning, so natively these are value conversions: wrong numbers,
  silently, with no `in_`/`extraout_` marker. `float_casts.py` finds ~14,400 such sites in 2,053
  Ghidra-sourced functions (~95% precision on a hand-checked sample; `float_casts.json`). The
  exception is `(int)F` in a function that contains `vcvt.s32.f32` (a real truncation, 1,363 sites,
  kept apart as ambiguous). Mechanically fixable in the converter: `(float)E` -> bit copy,
  `(int)/(uint)F` -> bit copy.
- **Functions Ghidra decompiled as empty** (`void f(void) { return; }`) while the ARM code does
  real work (float leafs that read r1 and return in s0, e.g. 0036EAF8): @EMPTY@ functions, table at
  the end. Their callers show `in_s0` after the call (class A) or a phantom `float fparam_N`
  parameter (not flagged at all: 0036E2F4, 0036E740, 0036F2A0, 004F9A2C...).
- **Functions whose Ghidra C silently drops a branch** (e.g. 00688C34 "chase" lost the
  step-down half). Only found by reading the disassembly.
- **False "does not return".** Ghidra treats 21 functions that do return (004FABDC, 00352210,
  004CF478, 00151148, 004BC8D8, 004ECF6C, 0057F260, ...) as non-returning, so 1,443 callers are
  cut off after the call (rest of the body and `return this` lost); 215 are reachable. Only
  0010C1B8 (SDK panic) really does not return. Table at the end (`false_noreturn.json`).
- **Bogus function starts** split real functions (0050B788/0050B78C, 00164284, 00100C90/00100C94):
  Ghidra then decompiles a prologue-less body with `in_r0`/`in_r1` as `this`.
- **Wrong return types.** The converter makes every non-float return `int` and Ghidra's `void`
  stays `void`: functions that tail-return a callee's r0 (0068C794 -> 00688C34) return garbage.
